# 交付流程 — 最小范围测试 → Lint → 验证 → 归档

> **来源**：deploy-git-isolated task 的多次踩坑教训。
> **核心原则**：**先跑通，再写文档**。文档是代码的镜像，代码不稳则文档必谎。

---

## 1. 反模式（踩坑记录）

### 1.1 反模式 A：先写文档再测试

```
写代码 → 写文档 → 测试 → 发现 bug → 改代码 → 文档已过时 → 返工改文档
```

**代价**：文档写两遍，时间翻倍，信任度下降。

### 1.2 反模式 B：全量测试后才敢提交

```
写完所有功能 → 开始测试 → 发现底层 bug → 全部推倒重来
```

**代价**：问题发现太晚，影响范围不可控。

---

## 2. 正模式：四步交付流

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  Step 1     │ → │  Step 2     │ → │  Step 3     │ → │  Step 4     │
│ 最小范围测试  │    │ Lint + 检查  │    │ 业务验证     │    │ 文档归档     │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
```

### Step 1: 最小范围测试（先跑通核心逻辑）

**原则**：不追求完美覆盖，先让主干逻辑转起来。

| 脚本类型 | 最小测试内容 |
|----------|-------------|
| `.ps1` | `[PSParser]::Tokenize` 语法检查 → 执行一次主要分支 |
| `.py` | `python -m py_compile` → 执行一次主入口 |
| `.json` | `ConvertFrom-Json` 解析 → 验证关键字段存在 |

**关键动作**：
- 只测试**新增/修改的最小功能单元**
- 不依赖完整环境（mock/局部 stub）
- 发现问题立即修复，不带着 bug 进下一步

### Step 2: Lint + 特定内容检查

| 检查项 | 工具/方法 | 强制？ |
|--------|----------|--------|
| 语法无错误 | `[PSParser]::Tokenize` / `python -m py_compile` | ✅ 强制 |
| 编码合规（UTF-8 BOM） | `check-file-encoding.ps1` | ✅ 含中文 PS 强制 |
| CRLF 检查 | `[System.IO.File]::ReadAllBytes` 查 0x0D | ✅ `.md`/`.ps1` 强制 |
| JSON 语法 | `ConvertFrom-Json` | ✅ 强制 |
| 敏感信息泄露 | 人工检查 PAT/密钥未硬编码 | ✅ 强制 |

### Step 3: 业务验证（端到端跑通）

**原则**：在真实环境（或准生产环境）执行完整流程。

| 验证项 | 通过标准 |
|--------|---------|
| 主功能路径 | 输入 → 处理 → 输出，结果符合预期 |
| 边界情况 | 空输入、异常输入、超时，行为可控 |
| 向后兼容 | 旧调用方式（无新参数）仍正常工作 |
| 性能可接受 | 无明显卡顿、内存泄漏 |

**关键动作**：
- 记录验证命令和输出（供审计）
- 发现异常立即停住，不回退到 Step 4

### Step 4: 文档归档（代码稳了再写）

**必须同步更新的文档清单**：

```
代码变更
    ↓
【必须】ENTRY.json — 版本号、脚本清单、状态
【必须】TASK-TOOLS-INDEX.md — 工具速查表
【必须】README.md — 场景导航、状态表
【按需】SOP-CHEATSHEET.md — 命令速查
【按需】PLUGIN-ARCHITECTURE.md — 架构设计
【按需】CHANGELOG — 变更记录
```

---

## 3. 流程检查清单（Checklist）

每次交付前，Agent 必须逐项勾选：

- [ ] **Step 1**: 最小范围测试通过（核心逻辑至少跑通一次）
- [ ] **Step 2**: Lint 无错误，编码合规，无敏感信息泄露
- [ ] **Step 3**: 业务验证通过（端到端执行，输出符合预期）
- [ ] **Step 4a**: ENTRY.json 已更新（版本号、脚本清单、场景映射）
- [ ] **Step 4b**: TASK-TOOLS-INDEX.md 已更新（工具速查表、边界矩阵）
- [ ] **Step 4c**: README.md 已更新（场景导航、当前状态表）
- [ ] **Step 4d**: 关联文档已检查（无断裂链接、无过时描述）

**未全部勾选 → 禁止标记为"完成"**

## 4. 本次实践的验证记录

| 轮次 | 问题 | 发现阶段 | 修复方式 |
|------|------|---------|---------|
| 1 | `$PSScriptRoot` 在参数默认值中为空 | Step 1 最小测试 | 参数默认值设空字符串，脚本体内补偿 |
| 2 | `github-api.ps1` 忘记加 UTF-8 BOM | Step 2 编码检查 | 重写文件加 BOM |
| 3 | `Read-EnvConfig` 返回 PSCustomObject，但 `github-api.ps1` 用字典访问 | Step 3 业务验证 | 统一改为属性访问 `$cfg.Pat` |
| 4 | 先写文档后测试，发现 bug 导致文档返工 | 反模式 A 实例 | 确立"先验证后文档"流程 |
