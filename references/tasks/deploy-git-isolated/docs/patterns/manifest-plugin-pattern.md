# Manifest + Plugins 扩展模式

> **来源**：deploy-git-isolated task 的工具索引与插件架构演进。
> **核心洞察**：同一套能力需要同时服务三类消费者——机器（脚本解析）、人类（快速定位）、开发者（渐进扩展）。单层结构无法同时满足。


## 1. 三层结构

```
┌─────────────────────────────────────────┐
│  机器层：ENTRY.json（真源索引）           │
│  - scripts[] / scenarios[] / active_scripts[]  │
│  - 被 Agent 工具调用前读取               │
├─────────────────────────────────────────┤
│  人类层：TASK-TOOLS-INDEX.md（速查表）     │
│  - 职责 / 典型场景 / 状态 / 边界矩阵      │
│  - 被开发者 Ctrl+F 搜索                  │
├─────────────────────────────────────────┤
│  代码层：lib-plugins/（可插拔实现）        │
│  - 拓扑排序自动加载                      │
│  - 新增 = 放文件 + 登记 JSON             │
└─────────────────────────────────────────┘
```

## 2. 各层职责边界

| 层级 | 消费者 | 内容 | 修改频率 | 禁止行为 |
|------|--------|------|---------|---------|
| **ENTRY.json** | Agent / 自动化脚本 | 结构化清单：路径、状态、版本、场景映射 | 随每次新增脚本更新 | 禁止内嵌长篇说明文字 |
| **TASK-TOOLS-INDEX.md** | 人类开发者 | 速查表：职责一句话、场景速查、边界矩阵 | 随功能变更更新 | 禁止复制完整代码 |
| **lib-plugins/*.ps1** | PowerShell 运行时 | 共享函数实现 | 按需新增 | 禁止隐式依赖 |

## 3. 修订联动规则

当新增/修改/删除脚本时，必须同步更新三层：

```
代码层变更（lib-plugins/*.ps1 或 scripts/*.ps1）
    ↓
【必须】更新 ENTRY.json（机器真源）
    ↓
【必须】更新 TASK-TOOLS-INDEX.md（人类速查）
    ↓
【可选】更新 SOP.md（标准流程）
【可选】更新 EXEC-CHEATSHEET.md（执行速查）
    ↓
【可选】更新 README.md（场景导航）
```

## 4. 边界矩阵的价值

TASK-TOOLS-INDEX.md 中的「边界矩阵」回答核心问题：

| 需求 | 首选工具 | 次选/备选 | 禁止行为 |
|------|---------|----------|---------|
| 验证 JSON 语法 | lint-json.py（通用） | — | 禁止用 python -c 内嵌验证 |

**价值**：防止重复造轮子、防止绕过既有工具、防止踩已记录的坑。

## 5. 复用条件

本模式适用于：
- 工具/脚本数量 >=5，需要索引
- 同时服务人类和机器两类消费者
- 能力持续演进，需要渐进式扩展
- 需要明确的"什么场景用什么"决策支持

## 6. 关联文件

- 机器真源：`ENTRY.json`
- 人类速查：`TASK-TOOLS-INDEX.md`
- 标准流程：`SOP.md`
- 执行速查：`scripts/EXEC-CHEATSHEET.md`
- 插件目录：`scripts/lib-plugins/`
